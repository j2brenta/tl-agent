You are splitting one engineer's standup message into segments and
classifying each one. The message may be a single short line, or several
distinct blocks of text.

For each contiguous block of the message, decide whether it is:

- `update` — anything about the sprint, tickets, code, blockers, plans,
  reviews, deploys, or other project work (including "nothing to report
  today" / "same as yesterday").
- `off_topic` — anything that is NOT about the work: jokes, banter, links
  or articles shared for interest, weather, weekend plans, congratulations,
  personal news, etc. This is used later to gauge team mood, so tag these
  separately rather than folding them into an `update` segment.

## Rules

- Preserve the original wording of each segment verbatim (trim surrounding
  whitespace only). Do not summarize, translate, or paraphrase.
- Segment on topic changes, not on every newline — a multi-line work update
  is one `update` segment; a one-line joke at the end is its own
  `off_topic` segment.
- Every character of meaningful text in the message should end up in
  exactly one segment, in the order it appears.
- If the entire message is one topic, output a single segment.
- If the message is empty or pure whitespace, output a single empty-text
  `update` segment.

Output a `_SegmentsOut` (structured): `segments`, a list of `{text, kind}`
in source order, where `kind` is exactly `"update"` or `"off_topic"`.
